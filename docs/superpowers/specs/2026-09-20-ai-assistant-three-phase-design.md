# AI 智能管家三期实施设计

## 目标

将 AI 智能管家从空白会话入口升级为可追溯的田间研判工作台。用户可选择田块与问题类型，查看数据适用性，得到结构化建议，并在当前 AI 运行期创建待人工确认的农事建议草稿。

## 固定边界

- AI 只生成建议、证据缺口和待确认草稿；不下发设备控制、灌溉、施肥、植保或农机命令。
- 厂家设备数据必须标注来源、采集时间和质量状态。未绑定地块、过期、缺失或质量异常的数据不可作为田间结论。
- AI 运行时配置、会话和建议草稿保持既有的进程内存存储；服务重启后清空。不得将 API Key 写入数据库、浏览器、本地日志或页面。
- 不接触既有业务 API 的写入锁，不改变真实观测的只读接口，也不将角色切换误作身份认证。

## 方案选择

采用“可追溯建议草稿 + 人工确认”的运行期工作流。纯前端改版没有业务闭环；直接写入既有农事 API 会绕过现有无登录认证环境下的写入安全边界。

## 一期：首屏、会话和提问

### 页面结构

1. 仅保留一个“AI 智能管家”主标题。
2. 顶部上下文条显示当前田块、作物、生育期、数据模式与最新数据状态；未选择田块时明确提示选择田块。
3. 新会话首屏显示三张任务入口卡：长势异常排查、水肥灌溉核查、病虫与盐分风险。
4. 输入区始终位于首屏并在小屏设备上固定在底部。
5. 会话列表按“今天”和“本周较早”分组，使用本地可读时间，不显示 ISO 时间戳。

### 交互

- 选择任务入口会填充问题模板，但不自动发送。
- 发送问题时将田块上下文与问题类型作为独立字段传给 AI Runtime。
- 无会话时显示任务入口与上下文选择；已有会话时显示消息与当前建议草稿。

## 二期：证据、结构化回答和建议草稿

### 田间上下文合同

每次提问可携带以下非敏感字段：

```text
plotId, plotName, crop, variety, growthStage, questionType
```

后端依据现有场景地块资料生成田块摘要。真实厂家设备只有在明确绑定田块并且数据可用时才进入证据列表；当前未绑定设备只显示为“未绑定地块，不参与判断”。

### 回答合同

每次完成的 AI 回答显示以下可见区块：

1. 判断：仅给出风险级别与条件性结论。
2. 依据：列出田块资料、设备或人工记录的来源、时间、质量状态。
3. 风险与限制：数据过期、缺失、未绑定或超出模型适用范围时明确说明。
4. 建议行动：人工可执行的巡田、补采样、核验等建议，不给出未经核验的生产处方或设备命令。
5. 待补证据：说明结论升级前仍需补齐的材料。

模型流仍为单次文本调用。前端用稳定的“回答说明”区块呈现运行时元数据，不能把模型文本伪装成已验证事实。

### 建议草稿

用户可把一条 AI 建议加入当前运行期的“待确认农事建议”。草稿至少包含：标题、关联田块、来源会话、创建时间、状态（待确认/已确认/已撤销）和原始建议文本。确认只改变 AI Runtime 内状态，不创建业务农事任务。

## 三期：协作、治理和移动端

### 协作状态

未发送问题时，右栏显示“本次回答将包含：判断、依据、建议行动、待补证据”，不显示伪造的等待流程。运行开始后，才显示规划、专家协作、交叉复核和总结的实际状态、已完成阶段与可见参与角色。

### 治理与降级

- 回答、草稿和运行状态均标明“本次服务运行有效”。
- 模型失败时保留用户问题与已获得的上下文；显示可重试提示及无需模型的证据核验清单。
- 数据异常仅影响相关证据项，不让页面整体变为空白。
- 草稿状态变化保留运行期时间线，供当前会话复核。

### 小屏布局

聊天区优先，田块上下文折叠展示；会话和协作区下移。输入框、发送和创建草稿操作保持可单手触达。

## API 与存储变更

扩展 `/api/ai-runtime`，不修改现有核心业务写入 API：

```text
POST /conversations/{id}/messages
  新增可选 context 字段，后端校验类型、长度和场景田块引用。

GET /conversations/{id}
  返回消息对应的安全上下文、证据摘要、运行元数据和本会话建议草稿。

POST /conversations/{id}/action-drafts
PUT  /action-drafts/{id}
  仅变更 AI Runtime 内存中的建议草稿状态。
```

所有写请求继续使用现有同源 JSON 与 AI Runtime 会话令牌校验。

## 验收场景

1. 新会话首屏可选择田块、任务入口并直接看到输入区。
2. 发送带田块上下文的问题后，公共会话响应不泄露 API Key 或内部错误。
3. 回答页面显示田块上下文、数据适用性、协作状态和结构化行动区域。
4. 未绑定或异常厂家数据被标为不可用于判断，不生成伪造读数或生产指令。
5. 建议可创建、确认、撤销为运行期草稿，且不会调用既有业务写入接口。
6. 无模型、模型失败和会话重启后均显示可理解的降级状态。
7. Python API 测试、AI Runtime 单元测试、前端 JavaScript 合同测试和浏览器关键路径验证均通过。
