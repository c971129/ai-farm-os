# AI 智能管家与 AI 与报告集成设计

## 目标

将 `/Users/a0/Documents/wrnc` 中已经实现的两项本地 AI 能力，作为当前 AI Farm OS 的独立功能集成进来：

1. **作物 AI 管家 → AI 智能管家**：提供真实模型驱动的文本会话、协作阶段可视化、会话恢复、请求幂等和容量保护。
2. **系统管理 → AI 与报告**：提供模型供应商管理、连接验证、默认供应商、能力模型映射及报告偏好配置。

现有“问一问 / AI 分析中心 / 政策问答”继续保持为仿真分析能力，不改变其数据来源和受控作业边界。

## 范围与角色

| 页面 | 农户 | 专家 | 监管 |
|---|---:|---:|---:|
| AI 智能管家 | 可见 | 可见 | 不可见 |
| AI 与报告 | 不可见 | 可见 | 不可见 |
| 既有政策问答 | 不变 | 不变 | 保持可见 |

当前项目的角色切换是界面呈现，不构成身份认证或授权边界。AI 与报告页面的供应商写入安全由同源校验和本地运行期会话令牌承担；它不应被表述为多用户权限系统。

## 架构

在当前 FastAPI 进程内新增隔离包 `backend/ai_runtime/`，而不是启动 wrnc 的独立 `8765` 服务。该包从 wrnc 的 `ai-local-backend/farmos_ai_local` 移植并适配其以下责任：

- `state.py`：进程内供应商、API Key、默认供应商和报告偏好；所有公开序列化结果删除 API Key。
- `providers.py`：OpenAI Chat Completions 兼容流与 Anthropic Messages 流；URL、DNS、响应体大小、超时和错误映射校验。
- `conversations.py`：会话、消息、运行记录、请求 ID 幂等、历史及正文容量限制。
- `agents.py`：一次真实上游流式调用，使用本地确定性规则选择展示角色，依序呈现规划、专家、复核、总结阶段；不执行工具调用。
- `api.py`：挂载 `/api/ai-runtime` 路由和运行期服务容器。

`backend/app.py` 只负责注册路由、维护服务生命周期，并让该精确前缀的运行期配置与会话写入使用自身令牌校验，而不受既有“仿真业务写入锁”阻断。其余 `/api/*` 的原有写入锁语义不变。

所有运行期 AI 状态仅存在内存：服务重启后供应商密钥、供应商验证状态、会话、运行记录和报告偏好均清空；不引入数据库迁移或配置文件持久化。

## API 合同与安全边界

所有新接口以 `/api/ai-runtime` 为前缀，并使用 `{ "data": ... }` 返回公开数据。至少包含：

- `GET /session`：返回服务启动时生成的会话令牌和公开运行状态。
- `GET/POST /providers`、`PUT /providers/{id}`、`POST /providers/{id}/verify`、`POST /providers/{id}/default`、`DELETE /providers/{id}/key`。
- `GET/PUT /report-settings`。
- `GET/POST /conversations`、`GET /conversations/{id}`、`POST /conversations/{id}/messages`。

对每一个改变运行期 AI 状态的请求，服务必须验证：JSON 请求体、同源 `Origin`、`X-FarmOS-Session` 与当前服务令牌匹配。API Key 只能通过写入请求抵达服务内存，随后永不在响应、HTML、浏览器存储、Cookie、文件或日志中出现。

供应商地址必须拒绝用户名密码、查询串、片段、私网、链路本地、保留地址和解析后指向这些地址的主机；仅回环地址可使用 HTTP，其余地址必须 HTTPS。连接验证只发送最小真实请求，并在前端提示可能产生少量模型费用。

对话仅支持文本：单次问题最多 4,000 字符，历史最多 12 条消息或 24,000 字符，最多 20 个会话和每会话 100 条消息，单次上游调用超时 45 秒，结果最大 64 KiB。一个进程同时只运行一个模型请求；同一 `requestId` 重复提交必须返回同一运行结果，其他活动请求返回可识别的容量冲突。

模型输出不得触发设备控制、工单、审批、文件写入或生产变更。报告生成和图像诊断的模型调用没有接通时，页面必须明确显示“尚未接通”，不得返回伪造结果。

## 前端与主题一致性

新增独立前端模块 `frontend/assets/ai-runtime.js`，由现有页面路由调用其 `renderAssistant` 与 `renderSettings`。新增页面不改变既有 `renderAI()` 的仿真逻辑。

导航将新增两个页面 ID：

- `assistant`：农户和专家菜单中的“AI智能管家”，图标采用既有导航图标系统。
- `ai_settings`：专家菜单“系统管理”组中的“AI 与报告”，图标采用既有导航图标系统。

页面视觉必须沿用当前项目已经存在的变量、圆角、浅色背景、深绿主色、青绿描边、信息卡、按钮、表单、空状态、提示条与响应式断点；不引入 wrnc 的独立视觉系统、外部字体或第三方 UI 库。新增 CSS 限定在 `ai-runtime` 命名空间，避免污染已有页面。所有新增静态资源版本统一升级到同一查询版本号。

AI 智能管家采用桌面三栏布局：会话列表、对话区、协作阶段；窄屏时顺序折叠。页面显示“作物全生命周期 AI 管家”副标题、可追溯阶段、发送状态和错误恢复入口。未配置或未验证默认供应商时，向专家提供跳转 AI 与报告的入口；农户只显示无法开始会话的真实原因，不暴露配置入口。

AI 与报告页面包含供应商卡片列表、供应商编辑表单、API Key 密码输入、验证与默认操作、能力模型映射、报告语言/引用/人工复核偏好。保存后立即清空浏览器中的 Key 输入框；列表仅显示 `keyConfigured`，绝不回填 Key。

## 错误处理

后端需以稳定代码区分：缺少或不合法会话令牌、供应商未验证、默认供应商未配置、远端认证失败、远端地址不安全、模型调用超时、流格式错误、请求容量超限、会话不存在、运行中冲突和重复请求。前端将这些代码映射为可行动的中文提示，不显示密钥、完整上游响应或内部堆栈。

若浏览器在请求已被服务接受后中断，前端通过会话详情重新对账已有 `requestId`，而不是盲目再次发送模型请求。若服务重启，前端识别令牌更新或会话缺失，清除本地仅用于界面恢复的标识并展示“服务已重启，运行期 AI 配置已清空”。

## 测试与验收

后端测试覆盖：

- 公开供应商数据不含 API Key，清除 Key 与修改供应商会清除验证/默认状态。
- 地址校验拒绝不安全 URL、私网地址及 DNS 绕过。
- 同源和会话令牌是运行期写入的必要条件。
- 报告偏好、供应商默认选择及模型映射的校验。
- 会话上限、消息上限、正文/历史上限、重复 `requestId`、运行中冲突和重启后清空。
- 本地假供应商的单次流调用、阶段标记解析、错误映射与无工具调用。

前端测试覆盖：菜单按角色显示、两个新页面可路由、API Key 不进入 DOM 的可读文本或浏览器持久化、请求状态机对接受后断链的对账逻辑，以及全部静态资源版本号一致。

浏览器验收使用本地假供应商完成新增、验证、设默认、创建会话、流式回答、刷新恢复和重启清空；自动化验收不连接外部收费模型。最终人工验收确认新增页面在桌面与窄屏下与现有主题一致，且原有 AI 仿真页面仍可使用。

## 不做的事

- 不接入设备控制、作业派单、审批、支付或任何生产写入。
- 不宣称报告生成或图像诊断已连接真实模型。
- 不引入用户账户、持久化密钥、多租户隔离或数据库迁移。
- 不替换现有仿真 AI 页面，不修改既有真实设备只读接入。
