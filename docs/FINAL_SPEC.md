## 1. 产品定位

**AI Farm OS** 是面向智慧农业的决策支持、证据协同与受控作业沙箱。仓库当前交付的是仿真系统，不宣称已连接生产遥测或真实执行设备。

核心理念：

`土地数字化 + 农业大模型 + Multi-Agent + IoT + 无人设备 + 数据资产`

系统目标：

将农业生产从「经验孤岛」升级为「可追溯感知 → 证据化研判 → 人工门禁 → 受控执行 → ACK/验收 → 持续改进」闭环。

仿真场景：新疆 AI 无人智慧农场 · **2000 亩** · 棉花 / 玉米 / 小麦。

目标场景（界面可展示，但必须同时标注“目标/模拟、待本场实测核验”，不得称为已达成 KPI）：

| 指标 | 目标值 |
|------|--------|
| 节水 | ≈ 20% |
| AI 病虫害识别 | ≈ 89.5% |
| 人工巡检下降 | ≥ 50% |
| 亩均综合增收 | 400–600 元 |

## 2. 总体架构（云-边-端）

### 2.1 分层

1. **感知层**：传感器、无人机、卫星、农机  
2. **数据层**：PostgreSQL、PostGIS、TimescaleDB、Milvus、Neo4j、MinIO  
3. **AI 层**：农业大模型、RAG、Vision、Prediction、Simulation  
4. **Agent 层**：Farm Master / Crop / Irrigation / Vision / Robot / Yield / Finance  
5. **执行层**：水肥设备、无人机、无人农机、机器人  
6. **商业层**：SaaS、数据资产、Agent 市场、模型市场  

### 2.2 闭环文案（驾驶舱常驻）

`传感器 → 数据平台 → 农业大模型 → Multi-Agent → 无人设备 → 生产反馈`

### 2.3 边缘

- MQTT Gateway  
- Edge AI  
- 本地缓存  
- 设备协议转换  

MQTT Topic 规范：

```
farm/{farmId}/device/{deviceId}/data
farm/{farmId}/device/{deviceId}/cmd
farm/{farmId}/agent/event
```

## 3. 功能全量清单（程序必须覆盖）

### 3.1 农业生产

- 农场管理、土地 GIS、作物与生育期、农事任务、水肥优化、产量预测  

### 3.2 智能系统

- 农业大模型问答、RAG 溯源、多智能体协同、知识图谱资产、数字孪生图层  

### 3.3 设备与执行

- 设备注册/状态/控制、MQTT 展示、无人机/农机/机器人调度  

### 3.4 商业与角色

- 农场版（管理员）、企业版（专家审核）、政府版（项目监管）  
- 数据资产 / 模型市场  

### 3.5 前端模块（按生产生命周期分组）

1. **指挥中心**：农业驾驶舱 · 数字孪生（墒情 / 长势 / 风险 / 机队 / 传感网格 / 单株表型）  
2. **精细农作**：植株精细管控 · 水肥中心 · 农事任务  
3. **全季装备**：播收到仓装备 · 多机联合作业 · 机器人调度 · 设备与传感网 · 厂家接入中心  
4. **收贮加工**：仓储与初加工  
5. **智能决策**：多Agent协同 · 联合诊断 · 协作工作台 · Agent 名册 · AI 分析中心  
6. **数据底座**：数据资产 · 云边端架构  

### 3.7 植株精细管控（强制）

- **单株数字孪生采样网**：每田代表性单株点（地上冠层 + 地下根系 + 全生育期形态）。  
- **地上**：活力、株高、LAI、NDVI、叶色、结实负荷。  
- **地下**：根活力、根深、密度、根际墒情、根尖活性。  
- **形态学谱系**：棉花/玉米/小麦全生育期阶段可追溯。  
- 入口：导航「植株精细管控」；孪生「单株表型」层；Ctrl+K 搜植株编号。  

### 3.8 全季装备与收贮加工

- **播收到仓装备**：整地→播种→巡田→水肥→防治→管护→机收→转运全阶段装备运行。  
- **仓储与初加工**：仓容/仓温仓湿、轧花/烘干清理/分级打包产线、批次追溯推进。  

### 3.9 导航目录（生命周期分组）

指挥中心 → 精细农作 → 全季装备 → 收贮加工 → 智能决策 → 数据底座

## 4. 国际优秀农业产品 UI 原则（强制）

参考国际组织、农业灌溉规范和农机安全/互操作标准，程序 UI 必须遵守。外部规范只作为设计依据；具体处方、阈值和设备能力必须绑定属地原文、适用版本与本场证据后才能用于生产。

| 规范依据 | 本项目实现映射 |
|---|---|
| [FAO Digital Agriculture and AI Innovation](https://www.fao.org/innovation/digital-agriculture-and-ai-innovation/en) / [FAO 路线图](https://www.fao.org/e-agriculture/documents-and-publications/digital-agriculture-and-ai-innovation-roadmap) | 数据治理、责任可追溯、农户数据权利、沙箱验证、模型局限与人工监督 |
| [USDA NRCS Irrigation Water Management 449](https://www.nrcs.usda.gov/resources/guides-and-instructions/irrigation-water-management-ac-449-conservation-practice-standard) | 灌溉建议必须说明时机、用量、速率、效率、根层/土壤与本地技术依据；缺项即 `NO_GO` |
| [ISO 25119-1 农林机械安全相关控制系统](https://www.iso.org/standard/69025.html) | 安全相关控制与普通业务 UI 分离；远程停止请求不冒充物理急停；恢复必须现场复核 |
| [ISO 11783 农机与农具串行数据网络](https://www.iso.org/standard/90373.html) | ISOBUS/任务控制器仅展示能力目录；生产互操作需通过身份、兼容、文件/任务交换和设备 ACK 验收 |

1. **决策优先，而非报表优先**  
   首页第一屏突出「此刻最该核验什么」（例如：B-01 墒情证据不足，补齐根层与传感器 QC 后再研判），原始图表下沉。  
2. **地图 / 地块中心**  
   地块状态用颜色编码（墒情、长势、风险），一眼可读，类似 Operations Center / FieldView。  
3. **渐进披露**  
   先告警与摘要，再详情、筛选、对比。  
4. **户外可读**  
   高对比文字、大字号关键指标、清晰状态色；避免低对比灰字堆叠。  
5. **动作可达**  
   灌溉研判、任务审核、设备模拟请求、Agent 协同应在上下文可达；高风险动作必须经过证据检查、角色门禁、人工确认和设备回执。  
6. **角色视角**  
   农场 / 专家 / 政府看到不同任务与监管重点。  
7. **品牌可识别**  
   第一视野必须强势呈现「一级芯界 AI Farm OS」，不可沦为通用后台模板。

## 6. 模块交互规范

### 6.1 农业驾驶舱

- 展示 KPI：仿真面积、Agent 能力数、设备模拟数、节水目标、增收目标；没有采集时间、来源和质量码时不得写成在线/实测  
- **优先核验条**：根据证据缺口和风险生成 1 条主核验事项 + 次要告警，不直接生成生产指令  
- 展示气象摘要、闭环文案、地块墒情+NPK、今日农事  

### 6.2 数字孪生

图层：`moisture | crop | risk | device | sensors`  
必须支持 AI 决策旁注与地块详情（作物、生育期、含水、长势、风险、NPK、传感点数）。

**展示规范（FieldView / Operations Center 类地图优先）：**
- 墒情：干棕→湿蓝连续色阶 + 阈值虚线环 + 地块内数值芯片  
- 长势：NDVI 惯例红黄→深绿 + 弱势边框强调  
- 风险：冷绿→热红 + 热核晕圈（高风险脉冲）  
- 设备：中性地块底图 + 分类型机队标记/状态环/标签  
- **传感网格**：单田多点多深度散点；选中地块高亮本田网点，其余降透  
- 色带图例与五图层 Tab 切换为孪生页标准交互 

### 6.3 Agent 名册与作物 AI 协同

**运营 Agent（执行层）**：状态、评分、工具、记忆；单 Agent 调度与 Farm Master 协同链。

**作物 AI 专家名录（能力层）**：落地文件 `frontend/assets/mxsj-agents.js`。

| key | 职责 |
|-----|------|
| master | 总管拆解与汇总 |
| crop-vigor / soil-health / vri-optimize / weather | 长势、土壤、水肥、气象（联合诊断默认组） |
| pest-alert / yield-predict / root-growth / breeding / phenotype | 病虫、产量、根系、育种、表型 |
| robot / finance | 设备调度、收益（名册扩展） |

**协同三页（规则编排仿真，不宣称真实模型或设备下发）：**

1. **多Agent协同中心** — 任务队列、分歧、证据缺口、人工门禁、追溯。  
2. **联合诊断** — 感知 → 联合分析 → 协同决策 → 执行复盘。  
3. **协作工作台** — 总管拆解 → 专家并行 → 交叉复核 → 总管汇总。

安全边界：协同中心不直接生成真实工单；诊断页标注「案例仿真」；工作台「只回答、不执行」。

### 6.4 设备与传感网

机队/网关与传感网格分列；按地块密度卡；展示 MQTT Topic、电量、厂家和数据时间。当前仅支持登记含 `vendor_id` 的沙箱设备与场景状态请求；生产启停必须另接服务端身份、互锁、命令签名、超时和设备 ACK。

### 6.4b 多机联合作业

候选编队任务 + 机具角色 + **联合调度智能体链** + 流程回放时间线；可出站到孪生/水肥/诊断/设备核验页。缺天气窗、药剂标签、试收、道路、仓容或人工批准时必须显示 `NO_GO`。

### 6.4c 厂家接入中心

展示厂家能力目录、协议和沙箱适配状态；SLA 统一标为待生产验证，接入动作只登记联调申请，不宣称已授权、已连接或健康。与设备清单双向跳转。

### 6.5 机器人调度

单机任务仿真进度 + 登记候选作业；不向真实设备下发。入口跳转多机联合作业与联合编队核验页。

### 6.6 AI 分析中心

LLM+RAG 溯源、Vision、产量预测、风险预测、模型版本。

### 6.7 水肥中心

按带单位、深度、时间、来源和质量码的墒情/养分证据形成候选处方。关键输入不全时返回 `NO_GO`；仿真系统只保存草稿，不下发真实阀泵。

### 6.8 农事任务

角色过滤；专家可审核。

### 6.9 数据资产

GIS/时序/影像/图谱/向量/模型 + 商业层标签。

### 6.10 云边端架构

六层架构图 + Edge 状态 + MQTT Topics + 仿真指标。

## 10. 工作区盘点结论（整合约束）

1. **唯一可运行产品面**：`ai-farm-os`（前端 `FarmEngine` + 可选 FastAPI）。  
2. **V20–V21 / Ultimate 压缩包**：几乎全为骨架桩，只作服务命名与文档来源，**禁止合并空壳 Java/Vue/Flutter**。  
3. **指标口径**：节水 20%、识别 89.5%、增收 400–600 元均为目标场景/模拟。只有附基线、样本集、统计周期、计算方法、质量码与验收人后，才可升级为“实测”。  
4. **后端必须与引擎 API 同构**：含 `fleet` / `vendors` / `devices?mesh=` / `role` / `orchestrate` / `robots` / `rag` / `risk` / `models` / `architecture` / `register` / `audit` / `priority`。  
5. **数据字段对齐**：地块 N/P/K、pest_risk、growth、sensor_count；设备 mqtt、battery、坐标、vendor_id、mesh；Agent memory/tools/score。  
6. **作物 AI 智能体**：专家名录与三页协同交互已并入前端；当前为规则编排仿真。  

*本节根据全量代码盘点并入规范，指导后续实现避免双轨漂移。*

- 田间、航拍、作物与设备图片使用本地真实感大田资料资产，按卡片居中裁切并标注“资料图/非实时”。  
- 监管端落实只读门禁：可关注、核查、取证与导出，不可创建任务、推进阶段或下发设备指令。

## 12. 安全、数据与验收硬约束（Final v1.2）

1. **默认拒绝执行**：仿真后端写操作默认锁定。缺证据、越权、跨农场、未知设备、紧急停止状态或非法状态迁移一律 fail-closed。
2. **观测与指令分离**：控制请求不得直接改写传感器观测、病虫风险、作物成熟度或设备 ACK；预测值也不得覆盖实测值。
3. **人在环状态机**：建议/`NO_GO` → 补证 → 人工确认 → 回放队列或受控命令 → 待设备 ACK → 待验收 → 已验收。当前仿真只走到“回放队列”；生产归档至少需要设备 ACK、轨迹/作业记录、实际面积或用量、独立验收人。
4. **农艺证据**：水肥至少需要作物/生育期、单位与采样深度、田间持水量、根层、ETc、有效降雨、灌溉效率与传感器 QC；植保至少需要物种、发生期、样方密度、当地阈值、标签和天气窗；采收至少需要成熟证据、含水率、试收损失和收储能力。
5. **农机安全**：远程“安全停止请求”不等同于物理急停。恢复前必须现场确认人员隔离、设备静止/状态、故障处置、复核人和通信链路。
6. **数据契约**：关键值必须携带 `value/unit/observed_at/source/quality_code`；空间数据必须有 CRS、版本和测绘来源。屏幕示意坐标不得用于导航、处方分区或面积结算。
7. **权限边界**：前端角色仅用于视图；生产部署必须另行实现服务端身份认证、RBAC/ABAC、租户和农场行级隔离、短期凭据、速率限制与不可篡改审计。
8. **内容安全**：所有外来文本输出编码；CSV 防公式注入；限制请求体、字段长度和跨域来源；不得把上游异常、密钥或内部路径回显给用户。
9. **可用性**：禁止后台自动整页重绘导致表单、焦点或滚动丢失；提供手动刷新、键盘导航、焦点恢复、触控目标和 320–1920px 响应式验收。
10. **发布门禁**：每轮必须通过 `verify.ps1`，并完成三角色、全部导航页、大屏、控制台、窄屏和桌面浏览器回归。P0/P1 未清零不得标记交付完成。
