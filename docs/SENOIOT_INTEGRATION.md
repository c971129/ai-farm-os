# 设备数据接入

## 本次交付

保持原有 FastAPI、SQLite 与静态前端结构，增加真实数据的采集、存储、历史查询和展示。真实设备观测与原有农事仿真独立，未将未绑定地块的传感器值替换到场景地块，也未实现任何厂家控制指令。

|---|---|---|

| 土壤墒情 | 864317086512400 | 土壤温度、湿度、EC |

土壤温度、湿度零值保留原始数值并标记 `CHECK_ZERO`，不据此推断正常或故障；由厂家核查探头、接线与字段映射。其他读数标记 `UNVERIFIED`，表示来自厂家但未完成现场校准核验。虫情识别结果为厂家自动识别摘要，未做现场物种复核，不能作为施药依据。

## 启动

1. 需要 Python 3.10 或更高版本。首次启动自动建立项目虚拟环境并安装原项目依赖。
2. 将 `.env.example` 复制成 `.env`，填写正式账号、密码；保持 `SENOIOT_ENABLED=1`。
3. 双击 `start.bat`。后台启动后自动打开 `http://127.0.0.1:8080/`。
4. 首页有真实观测摘要；“设备与传感网”和“厂家接入中心”有完整读数、历史曲线与 CSV 导出。
5. 保持后台窗口运行。关闭浏览器不影响采集；关闭后台窗口会停止采集。

原 `start-web.ps1` 是静态仿真与可选 AI 代理入口，不能采集真实数据。`打开系统.html` 提供正确入口说明及离线仿真入口。

当前机器的工作副本 `.env` 已配置用户授权账号，不打印、不返回浏览器、不放进交付 ZIP。转交部署人员时单独配置账号，勿通过前端代码传递。

## 后台配置

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| SENOIOT_ENABLED | 0（示例配置为 1） | 是否启动采集 |
| SENOIOT_ACCOUNT / SENOIOT_PASSWORD | 空 | 厂家正式账号密码 |
| SENOIOT_POLL_SECONDS | 60 | 最新读数采集间隔，最少 30 秒 |
| SENOIOT_HISTORY_SECONDS | 300 | 历史补数间隔，最少 60 秒 |
| SENOIOT_BACKFILL_HOURS | 1 | 新指标首次回补时长，1–720 小时；增大后分轮推进 |
| SENOIOT_STALE_SECONDS | 1800 | 读数和在线状态的过期提示阈值（30 分钟） |
| SENOIOT_DB_PATH | data/telemetry-账号摘要.db | 独立的真实数据文件；不同账号默认使用不同文件 |
| AI_FARM_PORT | 8080 | 启动端口 |

实际调用频率需要遵守厂家配额。启动器会加载 `.env`，已有进程环境变量优先；直接使用 `uvicorn backend.app:app` 时须由部署环境提供变量或显式加载 `.env`。

## 采集与一致性

- 固定 HTTPS 地址 `https://openapi.senoiot.com/open-api`，拒绝跨地址重定向；只允许登录、设备列表、物模型、实时和历史五种只读接口。
- Token 仅驻留服务内存，按过期时间提前更新；认证失效重登并重试一次。请求头为 `X-Api-Token`，不加 Bearer 前缀。
- `deviceId` 使用 DID，读数来自 `data.deviceData.result`。按原始毫秒 `timestamp` 保存采集时间，并独立记录同步时间。
- `vendor_devices` 保存实际设备，`vendor_metrics` 保存已观测指标，`vendor_samples` 保存历史，`vendor_cursors` 保存补数进度，`vendor_state` 保存同步状态。
- 厂家物模型不完整，因此只补充已观测指标的元数据，不凭物模型虚构传感器。
- 唯一键为 `(did, property, sample_time)`，重试及边界重叠不会新增重复点；旧历史入库不会覆盖更晚的最新读数。
- 历史每次查询固定时间段，忽略厂家的异常 `current/pages`。如果 `total` 大于返回条数，就继续缩小时间段，直到返回完整；检查 DID、指标、时间范围与重复点。
- 历史范围按北京时间提交，实时 Unix 时间戳按绝对时间处理。已通过实时记录与同期历史记录交叉联调，厂家时间字段的正式约定仍应记录到运维资料。
- 每轮历史最多 40 次请求，已完成窗口逐段提交；失败窗口不推进进度。下次带两分钟重叠继续补数，并给厂家写入留出一分钟延迟。
- 设备从账号列表移除后不再显示在实时列表，已采历史保留。异常时显示最后收到的数据与过期状态，绝不降级为仿真读数。
- 前端只读取本平台 SQLite 查询接口，刷新页面不触发厂家采集。当前曲线最多显示最近 2000 条；导出仅包含当前曲线记录并明确标注截断。

## 本平台接口

三个接口均为 GET，不开放远程触发采集、改配置或设备控制的入口。

```text
/api/telemetry/status
/api/telemetry/devices
/api/telemetry/history?device=<DID>&property=<属性>&start=<毫秒>&end=<毫秒>&limit=2000
```

历史接口支持 `before=<毫秒>` 游标向前翻页，返回 `has_more` 和 `next_before`。单次范围最多 31 天，条数最多 5000。CSV 防止公式注入；厂家名称和返回文本在前端进行 HTML 转义。

## 持续运行与迁移

本次是本机可运行的单账号只读接入，启动器仅监听 `127.0.0.1`。没有用户服务器地址和部署权限，因此未覆盖既有线上实例。也未将 Python 后台改写为 Cloudflare Worker 或上传真实观测与凭据到其他托管平台。

长期运行时在你们服务器部署原 Python 应用，由进程管理器运行：

```text
python -m backend.run --no-browser
```

必须保持单个采集进程（一个 worker），持久化保存 `data/`，通过经过身份认证的 HTTPS 反向代理提供访问；配置 `AI_FARM_ALLOWED_HOSTS` 与 `AI_FARM_ALLOWED_ORIGINS` 为实际受信域名。现有角色切换是仿真角色，不是登录认证，不能作为对外访问控制。

扩展到多农场时，需先确认实际设备与农场、地块的绑定及各用户的数据权限。目前所有实际设备明确显示“未绑定地块”，不会自动归入浏览器选择的仿真农场。读取厂家账号之外设备的权限不在本次范围。

部署备份应使用 SQLite 在线备份或停服务后一并保存数据文件，避免只复制写入中的主数据库而遗漏 WAL；账号密码单独保管。扩大首次回补范围只影响尚无游标的新指标；已有指标需要更早历史时应使用单独的回补作业，勿随意删除进度表。
