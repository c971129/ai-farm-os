# AI Farm OS 专家委员会与质量门禁

本项目采用多专业联合评审。任何“可执行建议”都必须同时通过农业合理性、设备安全、数据可信、软件质量和角色权限检查，不能只凭单一模型结论直接下发。

这些“专家”是系统设计与评审职责，不代表程序已经取得个人执业资格，也不替代属地农技、植保、农机安全或监管人员签字。当前版本的农业数值、设备状态、履历、图片和模型指标均为仿真数据；生产启用前必须换成有来源、时间、质量码和责任人的本场数据。

## 当前系统实现：独立 Expert Agent 委员会

前端与只读后端均实现了 10 个彼此独立的专家 Agent。每个 Agent 具有自己的证据包、硬性 `NO_GO` 条件、允许输出和国际设计依据；它们不读取同伴结论，不共享放行权限，不生成工单、处方、剂量或设备命令。

`/api/agents/council` 返回委员会契约；`/api/agents/council/review` 只生成一次性仿真评议预览，不产生数据库写入或设备控制。汇总器是只读组件：它只能归并证据缺口，**不能以多数投票覆盖任何一个 Agent 的 NO_GO**。

| 独立 Agent | 证据域 | 允许输出 | 必须阻断的典型情况 | 设计依据 |
|---|---|---|---|---|
| 农艺与作物健康 | 作物、品种、生育期、样方、属地制度 | 生育期判断、补证优先级 | 作物/生育期/区域模板不匹配；样方无时间位置 | FAO 数字农业与属地规程 |
| 水肥与灌溉效率 | 根层、ETc、有效降雨、流量、盐分 | 输入完整性、停止条件 | 单位/深度/QC 或水量输入缺失 | FAO-56、USDA NRCS 449 |
| 植保与生物安全 | 物种、病级、IPM、标签、天气、隔离 | 调查优先级、禁止条件 | 未确认对象/阈值；标签或漂移条件缺失 | FAO IPM |
| 农机装备与功能安全 | 身份、互操作、围栏、急停、ACK、机手 | 联锁缺口、人工放行前提 | 未验证兼容性、人员隔离、急停或 ACK | ISO 11783、ISO 25119 |
| 收贮加工与质量 | 含水、试收、批次、仓容、交接、卫生 | 收贮能力和追溯缺口 | 未校准含水/试收；仓容或批次链缺失 | Codex CXC 1-1969 |
| 空间数据与遥感 | CRS、测绘、影像时间、精度、边界版本 | 适用范围、精度限制 | screen demo 坐标用于导航或面积结算 | OGC API Features |
| 数据治理与可信 AI | 来源、质量码、模型版本、验证、漂移 | 可信度、模型限制、反馈要求 | 模拟数据冒充实时；模型无适用范围 | NIST AI RMF 1.0 |
| 农业物联网安全 | 设备身份、配置、更新、权限、日志 | 安全能力缺口、审计要求 | 最小权限、身份、审计或安全状态缺失 | NISTIR 8259A |
| 现场交互与无障碍 | 焦点、名称、对比、触控、窄屏、强光 | 可访问性和现场可读性回归项 | 关键状态只靠颜色；门禁不可键盘访问 | W3C WCAG 2.2 |
| 测试与可靠性 | 自动回归、异常输入、离线、越权、状态分叉 | 发布阻断项、可复现缺陷 | 高风险路径无测试；失败后仍显示成功 | 项目发布门禁与安全案例 |

委员会功能服务于“先补齐何种证据”的协作，不负责替人做农事、植保、机械、食品安全或监管决定。生产环境必须额外接入身份认证、资质库、属地规则库、真实数据来源、设备数字签名、审计留痕和线下安全验收。

## 专家角色

| 专家 | 主要职责 | 必须阻断的情况 |
|---|---|---|
| 农艺与作物专家 | 生育期、农时、水肥、病虫草害、采收阈值 | 作物/生育期不匹配；关键观测缺失；处方超出适用范围 |
| 农机与作业安全专家 | 机具匹配、道路冲突、作业窗口、维护和安全联锁 | 人机混行风险；机具能力不足；天气或地况不满足 |
| 灌溉与土壤专家 | 墒情、盐分、流量、轮灌和养分处方 | 单位/深度未知；水量超限；阀泵状态不可确认 |
| 产品与运营专家 | 首页决策优先级、责任人、截止时间、闭环 | 建议没有下一步动作、负责人、时限或回执 |
| 数据治理专家 | 来源、新鲜度、质量码、主键、版本与证据链 | 模拟数据冒充实时数据；来源/单位/时间缺失 |
| 软件架构专家 | 前后端契约、状态一致性、降级策略、可维护性 | 后端与本地引擎静默混用并产生状态分叉 |
| 测试与可靠性专家 | 单元、API、浏览器、响应式、回归与故障注入 | 关键流程无自动验证；异常路径不可复现 |
| 安全与权限专家 | 输入校验、最小权限、角色门禁、安全响应头 | 监管角色可执行生产指令；危险动作无确认或审计 |
| 无障碍与户外可读性专家 | 键盘、ARIA、对比度、触控目标、小屏适配 | 关键动作仅鼠标可用；状态只靠颜色表达 |

## 国际规范映射

- [FAO e-Agriculture](https://www.fao.org/e-agriculture/)：数字农业要结合可持续农业与农村发展场景；本系统据此采用数据来源、人工监督和本地化边界，而不把演示数据包装为实测数据。
- [FAO-56 Crop Evapotranspiration](https://www.fao.org/4/ah861e/ah861e.pdf) 与 [USDA NRCS Irrigation Water Management 449](https://www.nrcs.usda.gov/resources/guides-and-instructions/irrigation-water-management-ac-449-conservation-practice-standard)：灌溉建议必须能说明时机、用量、速率以及根层/土壤、有效降雨、效率和本地技术依据。本系统缺输入时不计算水量。
- [FAO Integrated Pest Management](https://www.fao.org/pest-and-pesticide-management/ipm/integrated-pest-management/en)：病虫害模块优先要求调查证据、阈值、非化学选项、标签和隔离条件，不产生药剂剂量或喷施指令。
- [ISO 11783-1](https://www.iso.org/standard/57556.html) 和 ISO 25119：以农机数据网络、任务交换和安全相关控制链为设计参考；未经过设备身份、兼容性、任务交换和 ACK 验收时，不标“已接入”。ISO 正式文本与认证要求须由获授权团队核对。
- [Codex CXC 1-1969 General Principles of Food Hygiene](https://www.fao.org/fao-who-codexalimentarius/en/)：收贮模块以批次、卫生控制点、交接和可追溯链为质量门槛，而不以模拟库存或质量数值作为生产结论。
- [OGC API Features](https://www.ogc.org/standards/ogcapi-features/)：空间数据应携带可发现的要素、CRS 与元数据；screen demo 坐标明确不得用于导航或面积结算。
- [NIST AI RMF 1.0](https://www.nist.gov/publications/artificial-intelligence-risk-management-framework-ai-rmf-10) 与 [NISTIR 8259A](https://csrc.nist.gov/pubs/ir/8259/a/final)：AI 输出应说明风险和人工监督；IoT 设备应以身份、配置、数据保护、软件更新、安全状态和日志能力为安全基线。
- [W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/)：关键状态需要文字与结构化表达、可访问名称、可见焦点和可用触控目标；这些原则同时服务于户外与弱网操作。

规范入口与版本说明见 `docs/FINAL_SPEC.md` 第 4 节；项目不复制标准全文，实施时应由具备授权的团队核对正式版本。

## 联合决策流程

1. 数据治理专家先确认来源、采集时间、单位和质量码。
2. 农艺/土壤专家生成候选建议，并列出适用条件与证据缺口。
3. 农机专家校验机具、人员、天气窗、道路和安全联锁。
4. 软件与安全专家检查角色权限、幂等、失败回滚和审计留痕。
5. 产品专家把结论转换为“动作、原因、风险、责任人、截止时间、回执”。
6. 测试专家执行自动回归；高风险动作必须保留人工门禁。

## 发布门禁

- `P0`：数据泄露、越权执行、危险机具/水肥指令、主流程不可用。必须清零。
- `P1`：数据口径错误、状态分叉、关键页面无反馈、移动端不可操作。必须有修复与回归测试。
- `P2`：视觉一致性、辅助说明、低频功能。纳入校准清单，不得破坏 P0/P1。
- 所有实时/在线/AI 指标都必须明确标注为“真实接入、后端仿真或本地仿真”之一。
- 每轮交付至少执行：Python/JavaScript 静态检查、API 冒烟、三角色权限回归、桌面与窄屏浏览器检查、控制台错误检查。
